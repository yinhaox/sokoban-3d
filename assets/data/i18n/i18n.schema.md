# i18n data: `en.json` and `zh.json`

Flat key/value translation tables loaded at runtime by
`src/logic/localization.gd`. Both files are UTF-8 JSON objects; every value is a
string. There are no nested objects and no comments.

| Field | Type | Meaning |
|---|---|---|
| `<key>` | string | One translation key. Keys are snake_case and never renamed once referenced by code or data. |

## Key groups

- `ui_*` — player-visible UI strings. A value may carry the placeholders the
  screen formats in, e.g. `ui_hud_moves` = `"Moves: %d"`.
- `level_NNN_name` — level names; the level JSON's `name_key` points at one.
- `ui_settings_value_*` — value formats for the settings screen.

## Rules

- Both locales must carry the same key set. `en` is the fallback: a key present
  in `en.json` but missing from `zh.json` still renders English instead of the
  raw key. `tests/run_tests.gd` asserts the coverage.
- Placeholder order and count must match between locales; only the surrounding
  text is translated.
- The files stay human-diffable: one key per line, stable key order.
