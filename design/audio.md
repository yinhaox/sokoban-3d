# Design: audio

_Every sound in the game, generated by project code and committed as WAV, with the licence and loudness rules a paid release needs. Owned by the technical artist._

## Goals

Pillar P1 (readable at a glance) and P4 (playable by everyone). Sound must confirm an action the player already sees, never carry information the screen does not show, and must be legal to ship without asking anyone.

- A fixed, short sound set generated deterministically by a committed script, with no third-party sample, loop or library.
- Every sound is audible in the default mix, distinct from its neighbours, and short enough to never mask a following action.
- Audio failure (no device, muted, suspended Web context) never blocks play and never changes rules.

The page lands when the generator script reproduces the committed WAVs byte-for-byte on a clean checkout, the loudness pass shows all files within the target range, and a silent-audio run still completes level 1.

## Player experience

The player hears the room, not a soundtrack. A step is a soft tap; a crate sliding is a short wooden scrape; a crate settling onto a plate is a warm thump with a quiet chime; a bump into a wall is dull and final. Undo sounds like the action rewound. The victory cue is four notes, brief, and never longer than the panel animation.

There is no music in 1.0 by design: a puzzle is easier to think in without a loop, and the asset constraint forbids licensed music. Volume sliders preview their effect immediately, and setting SFX to zero mutes everything without a click.

## Rules

**Generation.**

- All sounds are generated by `scripts/tools/generate_sfx.py`, a Python 3 standard-library script (no third-party package) that writes 16-bit mono PCM WAV at 44.1 kHz into `assets/audio/sfx/`.
- Random components (noise, pitch jitter) use fixed seeds per file, so the output is deterministic and reviewable as a binary diff.
- Every file gets a 2 ms fade-in and fade-out to avoid clicks, and is peak-normalized to `peak_dbfs` = -6 dBFS.
- The generator and the WAVs are committed together. Regeneration command: `python scripts/tools/generate_sfx.py --out assets/audio/sfx`.
- No sound is synthesized at runtime except pitch variation on playback.

**Sound set.** Durations are milliseconds; the recipe is the generator's synthesis description.

| File | Trigger | Duration | Synthesis recipe |
|---|---|---|---|
| `step_01.wav` .. `step_03.wav` | accepted player step | 45 | filtered white-noise burst plus 110 Hz sine body, 40 ms exponential decay |
| `push_01.wav` .. `push_02.wav` | accepted crate push | 130 | brown-noise scrape with a slow downward filter sweep, soft attack |
| `crate_land.wav` | crate settles on a goal plate | 160 | 95 Hz sine thump plus 1.2 kHz click, 120 ms decay |
| `goal_off.wav` | crate leaves a plate | 90 | short reverse click, 180 Hz body |
| `deadlock.wav` | deadlock warning chip appears | 300 | two 220 Hz pulses with 120 ms gap, low-pass |
| `undo.wav` | accepted undo | 130 | pitch-down noise sweep, mirror of `push_01` |
| `bump.wav` | rejected move | 80 | 75 Hz sine thud with fast attack, no tail |
| `win.wav` | level completed | 700 | four-note arpeggio C5-E5-G5-C6, sine plus 2nd harmonic, 80 ms per note |
| `star.wav` | one star appears on the victory panel | 220 | bell tone, sine plus 3.5x harmonic, 180 ms decay |
| `ui_move.wav` | focus moves | 30 | 1.2 kHz sine blip |
| `ui_confirm.wav` | button pressed | 70 | 880 Hz then 1.1 kHz sine, 30 ms each |
| `ui_back.wav` | back or cancel | 70 | 660 Hz sine, 60 ms decay |
| `unlock.wav` | a level unlocks | 350 | two rising tones 520 Hz to 780 Hz |

- No other audio plays in 1.0. Ambient loop, music and voice are out of scope.
- Sounds are non-positional: there is one player ear and the whole room is in front of it.

**Playback and mixing.**

- Bus layout: `Master` with one child bus `SFX`. A `Music` bus is reserved in the layout but silent in 1.0; settings keep its slider.
- Volume mapping: slider `0..1` maps to `linear_to_db(value)`, with `0` mapped to -80 dB (silent). Master and SFX gains multiply through the bus tree.
- There is a pool of `voice_count` `AudioStreamPlayer` nodes on the SFX bus, reused round-robin; a sound that arrives while all voices are busy replaces the oldest.
- Fast repeated triggers are throttled: `step_throttle_ms` for steps and pushes, `bump_throttle_ms` for bumps, so holding a direction or spamming a wall never stacks into noise.
- Step and push files are chosen by random index and played with `pitch_jitter` uniform variation, which is the only runtime variation.
- Sounds never change timing: no gameplay code waits on audio. Playback is fire-and-forget.

**Silence and failure.**

- If no audio device opens, the game runs muted, logs one warning, and settings still show the sliders; the failure is not a crash and is not a modal.
- If a WAV is missing or fails to load, that cue is silent, a warning names the file, and the game continues.
- On Web, audio starts only after a user gesture; the main menu's first button press satisfies this. The game does not show a "click to enable audio" overlay.
- Every sound cue has a visual counterpart already visible on screen; no rule, state or result exists only in audio. This is the contract that keeps the game playable muted and is restated in [accessibility.md](accessibility.md).

**Licence.**

- The WAV files are generated by this repository's own script; the studio dedicates them to the public domain under CC0 1.0, so any store build may ship them without attribution.
- The generator script is covered by the repository code licence recorded in [release.md](release.md) (MIT in 1.0).
- No sound library, sample pack, generated-model output or third-party loop is used, and the release credits page states that all audio is generated by the project.

## Edge cases

- **The player pushes a crate onto the last goal.** `crate_land` plays, then `win` after the victory delay; the two never overlap because the victory cue starts with the panel.
- **Undo is spammed.** Undo and push sounds share a throttle window; the player hears one rewind per `push_throttle_ms`, not a stutter.
- **The player holds a direction down a long corridor.** Step sounds play at the throttle interval, quieter than individual deliberate steps would feel; no machine-gun effect.
- **SFX volume is set to 0.** All cues are silent with no click and no pop, because the gain is applied at the bus, not by stopping playback.
- **The Web tab is backgrounded.** The browser suspends audio; on return, the next cue plays. No sound is queued or replayed.
- **Two stars appear at once.** `star` plays once per star with a 120 ms offset, not twice simultaneously.
- **A WAV is truncated or replaced by a zero-byte file.** That cue is silent, the warning names the file, and gameplay continues; the check command still passes because assets are not code.
- **The device sample rate is 48 kHz.** Godot resamples the 44.1 kHz files; no repitch is expected and QA compares the mix, not the samples.
- **The generator is run on another OS.** Fixed seeds and no platform-dependent randomness make the files byte-identical; a diff is a failure and the script is fixed instead.

## Open questions

1. **Music in 1.0 (creative director / technical artist, proposal).** None ships; the Music bus exists but is silent. Decision needed: confirm no music, or add a generated ambient loop and a real slider.
2. **Baked WAV versus runtime synthesis (technical director, proposal).** Baked files are deterministic and cheap. Decision needed: confirm the committed-WAV approach rather than `AudioStreamGenerator`, which would remove the asset files but add per-run cost.
3. **Positional audio (technical artist, proposal).** All cues are non-positional. Decision needed: whether crate sounds should come from the crate's world position in 1.0, which needs `AudioStreamPlayer3D` and a listener on the camera.
4. **CC0 versus reserved rights for the WAVs (release manager / producer, proposal).** The plan dedicates the generated audio to CC0. Decision needed: confirm, because CC0 also lets third parties reuse the studio's sounds.
5. **Loudness standard (technical artist, proposal).** Per-file peak normalization at -6 dBFS is the plan; there is no integrated LUFS target because there is no music bed. Decision needed: whether the store build needs an LUFS pass for the SFX bus.
